### ผู้ใช้

ออกแบบแผนการวางดัมมี่แทนจริงตอนไหนเตือนด้วยว่าจะลืมแทนของจริงจุดไหนหรือทำแพลนไว้

### ผู้ช่วย — ข้อเสนอ/รายงานในเวลานั้น

ได้ครับ สำหรับ **Mythic Academy ให้ใช้ดัมมี่เพื่อทดสอบการเล่นก่อน แล้วกำหนดจังหวะเปลี่ยนเป็นของจริงไว้ตั้งแต่ตอนวาง** ทุกชิ้นต้องมีรายการติดตาม เพื่อไม่ให้ฉากดูเสร็จแล้วแต่ยังมีของชั่วคราวหลงอยู่

แผนด้านล่างเป็นกติกาที่เสนอสำหรับโปรเจกต์ ยังไม่ได้ตรวจของที่มีอยู่ใน Roblox Studio จริงครับ

**1. แบ่งงานเป็น 5 ช่วง และเปลี่ยนของตามจังหวะนี้**

| ช่วง | ใช้ดัมมี่ทำอะไร | เมื่อไรต้องเปลี่ยน |
|---|---|---|
| 1 — วางพื้นที่ | กล่องแทนอาคาร พื้น ทางเดิน ประตู จุดวาร์ป | เก็บไว้จนทดสอบระยะเดิน มุมกล้อง และขนาดพื้นที่ผ่าน |
| 2 — ทดสอบระบบ | NPC หุ่นเทา ศัตรู ลูกบอลแทนสัตว์เลี้ยง ไอคอนชั่วคราว | เปลี่ยนหลังระบบหลักของสิ่งนั้นเล่นได้ครบหนึ่งรอบ |
| 3 — ทำพื้นที่ตัวอย่างให้จบ | เลือกส่วนหนึ่งของ Academy ทำภาพ เสียง และระบบให้ครบ | **ทุกจุดที่ผู้เล่นพบในเส้นทางตัวอย่างต้องเป็นของจริง** |
| 4 — ขยายพื้นที่ | ใช้ดัมมี่กับห้องหรือโซนใหม่ระหว่างพัฒนา | เปลี่ยนทีละโซนหลังผ่านการทดสอบการเล่น ไม่รอเปลี่ยนทั้งเกม |
| 5 — เตรียมเปิดทดสอบ | เหลือเฉพาะของที่ตั้งใจยังไม่เปิด | พื้นที่เข้าถึงได้ต้องไม่มีดัมมี่ที่ผู้เล่นเห็น; ส่วนไม่พร้อมต้องปิดทางเข้า |

**อย่าเริ่มทำโมเดลละเอียดก่อนล็อกขนาดและการใช้งาน** แต่ของที่กระทบการเล่น เช่น รูปร่างศัตรู ท่าโจมตี ประตู และแท่นกระโดด ต้องนำของจริงมาทดสอบเร็ว เพราะเปลี่ยนแล้วอาจทำให้การเล่นเปลี่ยนตาม

**2. แผนวางดัมมี่แยกตามพื้นที่**

| พื้นที่ / ระบบ | ใช้อะไรแทนก่อน | จุดเริ่มเปลี่ยนเป็นของจริง | จุดที่เสี่ยงลืม |
|---|---|---|---|
| Academy — อาคารและลาน | กล่องตามขนาดจริง | เมื่อเส้นทางจากจุดเกิดไปห้องเรียนและวาร์ปลงตัว | ด้านหลังอาคาร หลังคา ใต้บันได |
| ห้องเรียน | โต๊ะกล่อง เป้าฝึก หุ่นอาจารย์ | เมื่อเรียนและรับผลสำเร็จได้ครบหนึ่งบท | อุปกรณ์ที่ถือ ท่าสอน เสียง และข้อความบทเรียน |
| Dorm | เตียงกล่อง ประตูเรียบ เฟอร์นิเจอร์ตัวอย่าง | เมื่อเข้าห้อง วางของ บันทึกและโหลดห้องได้ | ภาพตัวอย่างเฟอร์นิเจอร์ จุดนั่ง และตำแหน่งเกิด |
| Dungeon | ห้องกล่อง หุ่นศัตรู บอสขนาดหยาบ | เมื่อจบรันได้ และรูปแบบโจมตีหลักลงตัว | ท่าเตือนโจมตี ศัตรูตาย หีบรางวัล และประตูทางออก |
| ทางลับ / ปริศนา | แผ่นสี สวิตช์ ลูกบาศก์แทนเบาะแส | เมื่อแก้ปริศนาได้โดยไม่ต้องให้คนทำบอกคำตอบ | ข้อความใบ้ เสียงตอบรับ และสถานะหลังแก้สำเร็จ |
| เกาะลับ | พื้นหยาบ สะพาน จุดลงจอด | เมื่อทดสอบวิธีไปถึงและกลับออกมาแล้ว | พื้นใต้เกาะ ขอบตก และจุดช่วยผู้เล่นติด |
| สัตว์เลี้ยง | ลูกบอลหรือหุ่นง่าย ๆ | เมื่อเดินตาม เรียกกลับ และเคลื่อนผ่านประตูได้ | ภาพในกระเป๋า ท่าหยุดนิ่ง และระยะห่างจากผู้เล่น |
| ชุด / เครื่องประดับ | ชุดสีพื้น รูปไอคอนชั่วคราว | เมื่อใส่–ถอดและบันทึกชุดได้ | ภาพพรีวิว การทะลุร่างกาย และการถืออุปกรณ์ |
| Aura | วงแหวนหรือเอฟเฟกต์เดียว | เมื่อกำหนดระดับความเด่นของแต่ละ rarity แล้ว | เอฟเฟกต์ตอนวิ่ง ตอนหลายคนอยู่รวมกัน และหน้าพรีวิว |
| คัมภีร์ / การ์ด / บันทึกโลก | รูปสีพื้นและข้อความทดสอบ | เมื่อรับของ เปิดดู และบันทึกการสะสมได้ | ภาพย่อ คำอธิบาย และหน้ารายการที่ยังไม่ปลดล็อก |
| วาร์ป | แผ่นพื้นพร้อมชื่อปลายทาง | เมื่อทดสอบไป–กลับและปลายทางพร้อม | ภาพโหลด ชื่อพื้นที่ จุดเกิด และกรณีวาร์ปไม่สำเร็จ |
| ร้านค้า / รางวัล | รายการและราคาทดสอบ | ก่อนเปิดให้ผู้เล่นใช้งานจริง | รูปสินค้า คำอธิบาย ของที่ได้รับ และราคาทดสอบ |

**3. ดัมมี่ทุกชุดต้องมี “บัตรงานเปลี่ยนของจริง”**

กำหนดรหัส เช่น `PH-ACA-001` และชื่อใน Studio เช่น `PH_ACA_Teacher_Alchemy` เพื่อค้นหาได้ง่าย โดยหนึ่งรายการอาจครอบคลุมกลุ่มของที่เปลี่ยนพร้อมกัน เช่น โต๊ะเรียนทั้งห้อง ไม่ต้องทำบัตรแยกทุกโต๊ะ

ข้อมูลที่ต้องมี:

| ช่อง | ตัวอย่าง |
|---|---|
| รหัส | `PH-ACA-001` |
| ตำแหน่ง | Academy → ห้องเรียนปรุงยา → จุดอาจารย์ |
| ของชั่วคราว | หุ่นเทาพร้อมข้อความสอน |
| ของจริงที่ต้องแทน | โมเดลอาจารย์ ท่ายืน ท่าสอน ภาพบทสนทนา |
| เปลี่ยนเมื่อ | บทเรียนปรุงยาแรกเล่นจบและรับรางวัลได้ |
| ผู้รับผิดชอบ | ชื่อคนทำหรือคนตรวจรับ |
| สิ่งที่ต้องตรวจหลังเปลี่ยน | ระยะกดคุย กล้อง ตำแหน่งมือ และทางเดิน |
| สถานะ | ดัมมี่ / พร้อมเปลี่ยน / เปลี่ยนแล้วรอตรวจ / ผ่าน |

**“นำโมเดลจริงเข้ามาแล้ว” ยังไม่เท่ากับ “เสร็จ”** ต้องเปลี่ยนทุกจุดที่ใช้งานและทดสอบหลังเปลี่ยนด้วย

**4. วางจุดเตือนไว้ในขั้นตอนงาน**

ใช้การเตือนตามเหตุการณ์ จะตรงจังหวะกว่ากำหนดวันลอย ๆ:

- **ก่อนเริ่มทำโซน:** เปิดรายการดัมมี่ของโซนนั้น และบันทึกของใหม่ทุกครั้งที่เพิ่ม
- **เมื่อระบบผ่านการทดสอบ:** เปลี่ยนสถานะดัมมี่ที่เกี่ยวข้องเป็น “พร้อมเปลี่ยน” และใส่งานแทนของจริงในรอบถัดไป
- **ก่อนประกาศว่าโซนเสร็จ:** ตรวจทั้งฉาก UI เสียง แอนิเมชัน และข้อมูลรางวัล
- **ก่อนรวมงานหรือย้ายเวอร์ชัน:** ตรวจว่าดัมมี่เก่าไม่ติดมากับสำเนาฉากหรือ prefab/template
- **ก่อนเปิดให้ผู้เล่น:** ต้องไม่มีรายการ “ดัมมี่” หรือ “รอตรวจ” ในส่วนที่ผู้เล่นเข้าถึงได้

สำหรับระบบช่วยตรวจใน Studio ให้กำหนด Attribute ไว้บนวัตถุต้นทาง เช่น `IsPlaceholder = true` และ `PlaceholderId = "PH-ACA-001"` แล้ววางแผนทำตัวสแกนรายงานแยกตาม Place ภายหลัง โดยต้องตรวจ UI และข้อมูลใน ModuleScript เพิ่มด้วย เพราะค้นหาโมเดลอย่างเดียวจะไม่เจอทุกอย่าง

**5. จุดที่ควรตรวจเป็นพิเศษ เพราะมักดูเหมือนเสร็จแล้ว**

- โมเดลจริงเปลี่ยนแล้ว แต่ **ไอคอนในกระเป๋ายังเป็นรูปเก่า**
- ศัตรูจริงมาแล้ว แต่ **Hitbox และระยะโจมตียังอิงหุ่นเดิม**
- ประตูสวยแล้ว แต่ **จุดกดใช้งานยังอยู่ตำแหน่งเดิม**
- เปลี่ยนฉากหลักแล้ว แต่ **ฉากสำเนา ห้องสุ่ม หรืออีก Place ยังใช้ดัมมี่**
- ของรางวัลจริงแล้ว แต่ **ชื่อ คำอธิบาย และภาพแจ้งรับรางวัลยังเป็นข้อความทดสอบ**
- ลบวัตถุทดสอบแล้ว แต่ **สคริปต์ยังสร้างมันกลับมาตอนเริ่มเกม**
- เอฟเฟกต์ดูดีคนเดียว แต่ **เมื่อหลายคนใช้พร้อมกันลายตา** โดยเฉพาะ Aura
- ปิดพื้นที่ไม่พร้อมแล้ว แต่ **วาร์ปหรือเควสต์ยังส่งผู้เล่นเข้าไปได้**

**ลำดับที่แนะนำให้ทำของจริงก่อน:** จุดเกิด → เส้นทางเข้า Academy → อาจารย์และบทเรียนแรก → หน้ารับรางวัล → ห้องพักตัวอย่าง → Dungeon หนึ่งรัน ส่วนนี้จะเป็นตัวอย่างมาตรฐานสำหรับขยายทั้งเกม

แผนนี้ใช้เป็นจุดตรวจงานได้ทันที ส่วนการแจ้งเตือนอัตโนมัติยังไม่ได้ตั้ง เพราะยังไม่มีวันหรือรอบตรวจที่กำหนดครับ
