# Mythic Academy

โปรเจกต์ Roblox โรงเรียนเวทมนตร์ต้นแบบ พร้อมเอกสารออกแบบและ Rojo codebase ใน workspace นี้

## สถานะปัจจุบัน

Build หลักใช้หอพัก v2 แล้ว มีบทเรียนแรงลอยตัวและแสงนำทาง และม่านคุ้มกันสามเวท กลไกนอกห้องเรียน สมุดนักเรียนพร้อมคัมภีร์ คู่หูละอองหูใบพร้อมชื่อและความผูกพัน ดันเจียน 3 ห้อง (ปริศนา → ผู้เฝ้า → ห้องจบ) พร้อม checkpoint และหอพักวางเฟอร์นิเจอร์พร้อม preview

Step 56 เพิ่มคลื่นเวทโจมตีผู้เฝ้าหลังผ่านม่านคุ้มกัน กด C หรือปุ่มบนจอ โจมตี 4 ครั้งเพื่อผ่านห้อง 2 ได้ และสมุดแสดงขั้นความชำนาญจากบทเรียน/การจบดันเจียนที่บันทึกเดิม ยังไม่มี EXP วัสดุฟาร์ม หรือร้านขายของ

ผลตรวจล่าสุด compile Luau 95 ไฟล์และ tests 1291 assertions ผ่านบน API doubles; Rojo build ทั้งสอง project และทะเบียนดัมมี่ 97 แถวผ่าน ยังไม่ตรวจภาพ/เล่นจริงของ combat ชุดนี้ มือถือจริง เครือข่าย หรือ DataStore จริง และยังไม่เผยแพร่เกม ดู [Step 56](docs/STEP_56.md)

## เริ่มพัฒนา

ใช้ Rojo 7.7.1 ตาม `aftman.toml`:

```sh
aftman install
mkdir -p build
rojo build default.project.json -o build/MythicAcademy.rbxlx
rojo serve default.project.json
```

การเชื่อม Studio สำหรับผู้พัฒนา: ใช้ปลั๊กอิน Rojo ที่ `127.0.0.1:34872` D61 อนุญาตตรวจ Studio แล้ว แต่เครื่องมือ CUA เชื่อมต่อไม่สำเร็จในงานล่าสุด จึงยังไม่มีผลตรวจภาพของการแก้ชุดล่าสุด

| ไฟล์ต้นทาง | ตำแหน่ง Roblox |
|---|---|
| `src/server` | `ServerScriptService.MythicAcademy` |
| `src/client` | `StarterPlayer.StarterPlayerScripts.MythicAcademy` |
| `src/shared` | `ReplicatedStorage.MythicAcademy` |
| `src/world` | `Workspace.AcademyPrototype` |
| `src/dorm` | `ServerStorage.MythicAcademy` |

ฉาก blockout อยู่ในไฟล์และเห็นก่อน Play ตาม mapping; สิ่งที่เพิ่มเองใน Studio ต้องบันทึก place แยก การ build จากไฟล์ไม่รวมการแก้ฉากที่ยังไม่ส่งกลับเข้า source

## วิธีใช้ต้นแบบ

จุดเกิดอยู่ทางใต้ของลานแกนแสง (ผังใน [SCENE_DESIGN_SLICE.md](docs/SCENE_DESIGN_SLICE.md)) ทุกจุดยังเป็นกล่องสี blockout

1. ห้องเรียนแรงลอยตัว (เหนือลาน ฝั่งซ้าย) แท่นม่วง: เริ่มบทฝึก ยกผลึกถึงระดับ 9 แล้ววาง
2. แท่นฟ้าที่ขอบลานด้านตะวันตกเฉียงเหนือ: ใช้เวทกับกลไก ระดับ 12 แล้วรับบันทึกจากแท่นทองในโถงระหว่างห้องเรียน
3. หลังรับบันทึกแล้ว ทดลองเวทแสงที่ห้องเรียนแสง (เหนือลาน ฝั่งขวา) สลับอักขระให้ได้ 1สว่าง–2ดับ–3สว่าง ผ่านแล้วไปสวนอักขระทางตะวันออกแก้เป้าหมาย 1ดับ–2สว่าง–3ดับได้ ผ่านบทแสงแล้วบันทึกไว้หลังออกเกม (ผลสำรวจลานยังไม่บันทึก)
4. หลังผ่านบทแสง ไปสนามฝึกทางตะวันตกเฉียงใต้ กด Q หรือปุ่มให้ตรงจังหวะ กัน 2 จาก 3 ครั้ง (ผ่านแล้วบันทึกไว้)
5. เปิดสมุดด้วย B เรียก/เก็บคู่หูด้วย P หรือปุ่มบนจอ ปุ่ม "เล่นด้วย"/"เปลี่ยนชื่อ" อยู่ใต้ปุ่มคู่หู ความผูกพันเพิ่มจากกิจกรรมครั้งแรกที่พาคู่หูไปด้วย (เล่น, ค้นพบอักขระสวน, จบดันเจียน, เข้าหอพัก)
6. ผ่านสวนอักขระขึ้นเหนือไปซากวิหาร: ดันเจียน 3 ห้อง — ห้อง 1 ยกผลึกถึงระดับ 11 เปิดประตู; ห้อง 2 หลบแนวยิงสีม่วงของผู้ยิง ผ่านผู้เฝ้าโดยโจมตีคลื่นเวท 4 ครั้ง (หลังผ่านม่านคุ้มกัน), หยุดที่แท่นควบคุมระดับ 10 ช่วงพัก หรือกันด้วยม่านคุ้มกัน 2 ครั้ง แล้วผ่านเงาที่ประตูหลักด้วยอักขระแสง หรือเดินอ้อมไปประตูข้าง; ห้อง 3 รับผลที่แท่นจบ ทุกห้องมีประตูกลับโรงเรียน
7. ทางตะวันตกของลาน: ประตูหอพัก เลื่อน/หมุน preview แล้วยืนยัน เก็บ หรือเลือกชิ้นถัดไปได้เฉพาะชิ้นที่เป็นเจ้าของ

เวทใช้ R ยก / F ลด / G วาง / X ยกเลิก หรือปุ่มบนจอ รายการข้างต้นเป็นพฤติกรรมโค้ดที่ทดสอบบน doubles ยังไม่ใช่ผลเล่นจริง

## ข้อมูลและการตรวจ

Studio ใช้ memory adapters ข้อมูลหายเมื่อ Stop; server จริงมีโค้ด DataStore แยก progress กับ dorm โดยห้องใช้ schema v2 และ lease migration ผู้เล่นเดิมได้ม้านั่งเดิมหนึ่งชิ้น ไม่มีการแจก Stool อัตโนมัติ การ rollback writer เป็น v1 อ่านข้อมูล v2 ไม่ได้ ดู [Step 27](docs/STEP_27.md)

```sh
python3 scripts/check_luau.py --bin-dir /path/to/luau-tools
```

ใช้ official Luau CLI ที่มี `luau`/`luau-compile` รายงานสร้างที่ `build/luau-checks.json` คำสั่งนี้รัน `scripts/check_placeholders.py` (ตัวตรวจดัมมี่เทียบทะเบียน ASSET_TRACKER ไม่ต้องใช้ Luau) ก่อนเสมอ และ GitHub Actions `placeholder-check` รันตัวตรวจนี้กับ tests ของมันทุก push/PR ดู [ขอบเขตผลตรวจล่าสุด](docs/STEP_55.md)
