# Step 13 — เป้าหมาย checkpoint และสรุปรัน

เพิ่ม DungeonViewModel อ่าน attributes ของ server และแสดงผลใน HUD เดิม/สมุดนักเรียน ไม่เพิ่มสิทธิ์รางวัล remote หรือข้อมูลถาวร

- HUD เปลี่ยนจากบทเรียนเป็นเป้าหมายดันเจียนตามสถานะ Puzzle / Reward / Complete
- แสดง checkpoint จุดเริ่มหรือใกล้แท่นจบ และวิธีไปต่อเมื่อรันพักหลังตาย
- ระหว่างควบคุมเวทยังคงแสดงคำใบ้/วางผิดจาก LessonHint เพื่อไม่ซ่อน feedback ที่ต้องใช้แก้โจทย์
- สมุดแสดงรายละเอียดปริศนา/ผลหยุดผู้เฝ้าแบบทางเลือก/จุดกู้คืน/ข้อจำกัดผลทดลองเฉพาะรอบเล่น
- ข้อมูลไม่พร้อม/ไม่รู้จัก state จะไม่แสดงสรุปสำเร็จ; ออกเป็น Idle แล้วกลับ HUD บทเรียน ไม่เก็บประวัติรันย้อนหลัง

## ผลตรวจ

Luau compiler 29 ไฟล์ผ่าน; tests เดิม 247 + view model 49 = 296 assertions ผ่าน รวมสถานะรัน การพัก checkpoint และผลผู้เฝ้า; flow services เดิมยังผ่าน Rojo build/sourcemap/XML และ whitespace ผ่าน

ไม่เปิด Studio ตาม D16 ยังไม่ตรวจภาพ/การตัดคำไทย/ขนาด HUD/การเลื่อนและ client UI runtime โดยเฉพาะมือถือ จึงยังเป็น UI ต้นแบบ ไม่เพิ่มการรับรองภาพจาก model tests

ขั้นถัดไป: แยกตัวควบคุมเวทและ HUD จาก Main.client เพื่อทดสอบการสร้าง/เก็บภาพและ event updates ลดความเสี่ยงสะสมก่อนเพิ่ม UI/ห้องใหม่
